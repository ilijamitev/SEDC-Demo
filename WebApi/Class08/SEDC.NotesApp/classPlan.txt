### RECAP
=> sporedba na trite ORMs (pros & cons)
=> zavisno od potrebite, najcesto najzgodno e kombinacija od dve alatki....
	pr. Dapper za READ, EF za WRITE
	pr. EF + ADO.NET za optimiziranje na nekoi kverinja



1. ADO.NET
	Pros:
		- Full control over SQL queries and database operations.
		- Efficient for simple and high-performance scenarios.
		- Can work with any database that provides a .NET data provider.
	Cons:
		- Involves writing a lot of repetitive boilerplate code.
		- Manual mapping of data between database records and objects.
		- Prone to SQL injection if not used properly.

2. DAPPER
	Pros:
		- Lightweight and fast (micro ORM).
		- Direct mapping of query results to objects.
		- SQL injection protection through parameterized queries.
	Cons:
		- Requires manual SQL query writing thus good SQL knowledge.
		- Limited support for complex relationships between objects.

3. EntityFramework
	Pros:
		- Rapid development with automatic SQL generation.
		- Rich support for relationships, migrations, and database schema management.
		- Object-oriented querying using LINQ.
	Cons:
		- Can introduce some performance overhead compared to raw ADO.NET or Dapper.
		- Might not be suitable for high-performance scenarios or legacy databases.
